## 1. Сценарий (зафиксирован пользователем)

1. Пользователь строит помещение (стены → авто-зона).
2. **Контекстное меню** на выбранном помещении → тип помещения по СП 54.
3. Пользователь сам ставит **терминалы и установку** до наброска; агент **до трассировки**
   даёт развёрнутую рекомендацию по выбору оборудования (типы помещений + общая площадь)
   и по правилам каждого типа помещения.
4. Пользователь рисует **всю трассу притока и всю трассу вытяжки полилиниями** на 2D-плане —
   не выбирая сечения и типы фиттингов.
5. Кнопка **«Трассировка»** — агент распознаёт трассу, подбирает сечения по СП 60 исходя
   из типов помещений, выбирает фиттинги на сопряжениях магистраль/ответвления, строит
   вертикальные переходы и утки, материализует реальные узлы.
6. Расширенный режим: **автотрасса к ближайшей магистрали** (ответвления к терминалам).
7. Контроль высот — модель «как в Revit»: ось на вершинах эскиза, авто-вертикали,
   нормативные проверки (см. §4).
8. Проверка **баланса П/В** — обязательна.
9. Существующий duct-инструмент **дорабатывается** (режим эскиза), параллельных инструментов нет.
10. Регенерация: повторная «Трассировка» полностью перестраивает сеть (ручные правки
    построенных трасс теряются — принято).

## 2. Архитектура

### 2.1 Модель эскиза (W6 — персистентность)

Новый узел `DuctSketchNode` (один на уровень): полилинии эскиза
`{ system: 'supply'|'exhaust'|'return', points: [{x, z, elev?: 'auto' | { axisM: number }}] }`.
- Рендер на 2D-плане: пунктир цветом системы; в спецификацию/DXF/экспорты **не попадает**.
- Эскиз — источник истины для регенерации; «Очистить эскиз» — отдельная команда.
- Duct-инструмент получает **режим «Эскиз»**: рисует в эскиз, не в узлы; `S` — система (уже есть).

### 2.2 Конвейер агента (порядок фиксирован, W4)

```
0. Валидация эскиза (блокеры/предупреждения)          → validate-sketch.ts   (W1, W13)
1. Распознавание топологии: разрез в точке установки,  → recognize-topology.ts (W1)
   привязка концов к установке/терминалам, допуск связи
2. Назначение помещений терминалам + расходы (СП 54)   → flows.ts             (W2)
   + баланс П/В (обязательный) + монотонность ветка≤магистраль (W9)
3. Подбор сечений: скоростной метод СП 60 | равных потерь (опция, как в Revit)
4. Высоты: оси вершин, авто-вертикали, проверки        → elevations.ts        (§4)
5. Магистрали: сегменты + фиттинги по «Предпочтениям»  → routing-preferences.ts, fittings.ts
6. Ответвления: автотрасса терминал → магистраль      → branches.ts
7. Утка на всех П/В-пересечениях (planAllBypassRuns)
8. Финальная валидация; неразрешённое — в отчёт (лимит итераций)
9. Материализация одной undo-командой + панель «Решения трассировки»
```

### 2.3 Предпочтения трассировки (аналог Revit Routing Preferences)

`packages/core/src/mep/routing-preferences.ts` — редактируемые данные (не код):
- фиттинг сопряжения магистраль/ответвление: тройник / седелка (по отношению сечений);
- угол врезки ответвления: 45° (приоритет — меньше потери) / 90°;
- радиус отводов R=1D / R=1.5D; метод подбора (скорость СП 60 | равные потери, Па/м);
- допуск подключения терминала к магистрали, м; зазор утки (BYPASS_MIN_GAP_MM).
UI: секция в панели «Вентиляция». Каждое решение агента аннотируется
(«участок → Ø315, СП 60, v=4,2 м/с»; «утка: пересечение с П1»; «переход Ø200→315»).

### 2.4 Рекомендации (обязательные, W7/W8)

`packages/core/src/mep/equipment-catalog.ts`: номенклатура установок РФ
(приточная / вытяжная / приточно-вытяжная с рекуперацией / канальный / крышный вентилятор)
+ правила выбора по типам помещений, площади и балансу. Рекомендация — **совет со ссылками
на нормы и статусом верификации** (`TABLE_L3_VERIFIED`, `FITTING_ZETA_VERIFIED` показываются
прямо в панели), не решение за пользователя. До трассировки — панель «Рекомендация оборудования».

### 2.5 Высоты (модель Revit, §4 PLAN-анализа)

- Ось хранится на вершинах эскиза: `auto` (агент: потолок помещения − зазор − H/2, считается
  на построении — верх держит плоскость под потолком) или `fixed` (число, м).
- Разные оси соседних вершин → вертикальный участок + 2 отвода R=1.5D (автоматом).
- Опуски/подъёмы к терминалам и установке — автоматом по разнице отметок патрубков.
- Проверки: верх ≤ перекрытие − зазор (вкл. изоляцию); параллель П/В — смещение в плане,
  разворот по высоте только при узком коридоре (с предупреждением); пересечение — утка.
- Отметки оси/низа — в DXF и спецификацию (ГОСТ 21.602).

## 3. Карта митигаций (из анализа слабых мест)

| Риск | Механизм в плане |
|---|---|
| **W1** Топология эскиза (пустые концы, самопересечения, установка в середине, 2-я полилиния) | Этап B1: валидация с конкретными ошибками; разрез пути в точке установки; привязка концов обязательна; допуск связи — правило с визуализацией |
| **W2** Тихо неверное назначение помещений терминалам | Этап B2/C1: таблица «терминал ← помещение ← расход» на подтверждение перед построением |
| **W3** Нормы неисполнимы на заданном пути | Политика эскалации: блокеры (не строить) vs предупреждения (строить best-effort + красные маркеры нарушений); никогда не молчать |
| **W4** Порядок утки и авто-ответвлений | Фиксированный конвейер §2.2; лимит итераций; неразрешённое — в отчёт |
| **W5** Регенерация стирает правки | Предупреждение перед rebuild со списком пересоздаваемого; один undo-шаг |
| **W6** Персистентность эскиза | `DuctSketchNode` в сцене; исключён из экспортов |
| **W7** Ответственность рекомендаций оборудования | Только со ссылками на нормы, пометка «рекомендация», консервативные дефолты |
| **W8** Невифицированные константы | Статусы верификации показываются в рекомендациях и панели решений |
| **W9** Ветка толще магистрали | Валидация монотонности расходов терминал→установка до подбора |
| **W10** Тип помещения должен переживать регенерацию зон | Контекстное меню работает для авто- и ручных зон; тест на сохранение `spaceCategory` в update-пути |
| **W11** 2D-эскиз скрывает 3D | Панель «Решения трассировки» + отметки на плане после построения |
| **W12** Производительность | Весь расчёт — по кнопке; живой превью нет |
| **W13** Частичные сценарии (нет установки/вытяжки, эскиз вне габаритов) | Actionable-ошибки валидации, построение только валидного |

  build-plan (параллельные П/В ближе 0.3 м, не стык у установки), тест.
- **W5 предупреждение перед rebuild** — в панели показывается «пересоздаст N узлов прошлой
  сборки — ручные правки потеряются» при наличии `metadata.agentRouting`.
- **W8 статус верификации** — `FITTING_ZETA_VERIFIED=false` выведен в футер «Расчёт сети»
  (в дополнение к `TABLE_L3_VERIFIED` в рекомендациях).
